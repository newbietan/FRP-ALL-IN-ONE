# 隧道重新启用后不可用：排查与源码修复

## 不能等同的三个状态

- **设备在线**：Agent 与管理 API 的 WebSocket 已连接，不代表 FRPC 已连接 FRPS。
- **配置保存/下发成功**：数据库已更新或配置已送达 Agent，不代表 FRPS 已接受代理。
- **代理注册成功**：FRPS 已接受隧道；仍不保证客户端能连接配置中的目标 IP/端口。

面板当前的隧道状态主要来自启用配置与设备状态，不是端到端连通性检查。

## 已确认的根因：显示名被当成全局代理名

现场客户端为 v3.2.11，日志持续报告 `proxy [ubuntu.SSH] already exists`，约每 33 秒重试。用户确认两台设备的主机名都为 `ubuntu`，隧道名都为 `SSH`。这属于合法显示需求，不应要求用户改名。

旧配置生成逻辑用 `设备显示名.隧道显示名` 作为 FRPS 的全局代理名，导致两台设备争用 `ubuntu.SSH`。只有先注册的一方能成功；关闭该隧道可能让另一台设备的重试抢先注册，原设备重新启用后便持续收到重名错误。这不是防火墙未放行，也不是此次现场的首次登录失败。

同一设备内创建两个同名隧道也存在类似问题；修改显示名称还会无意义地改变内部代理身份。

## 本地回归证据

- 后端回归测试在修复前复现跨设备重名、同设备隧道重名和显示名称修改引发的身份变化；修复后三项均通过。
- 真实 FRPS/FRPC 复现两客户端争用 `ubuntu.SSH`，随后分别按两种迁移顺序应用唯一内部标识，两台设备都恢复实际转发；分别关闭和重新启用任一方，另一方仍能正确转发到自己的目标。
- 单设备正常 TCP 隧道连续关闭、启用 5 次也通过。
- 另行复现了首次 FRPS 连接失败后内核退出、注册端口冲突却过早报告成功等健壮性问题；它们与本次已确认的重名根因分开处理。

## v3.2.13 修复

### 服务端：内部标识与显示名称分离

- 内部代理名改为 `client-<完整设备 ID>.tunnel-<隧道 ID>`，不使用主机名、隧道显示名或其截断值。
- 设备列表与隧道显示名称仍来自原数据库字段，可以重复；不会要求用户改主机名或隧道名。
- 关闭、重新启用和修改显示名称都不改变内部标识；两台设备与同设备内不同隧道互不争用代理名。
- 不抢占或强制删除其他客户端的同名代理，也不需要删除设备、数据库或重装客户端。

### 客户端：真实就绪确认与连接恢复

- Agent 托管的 FRPC 核心统一启用持续登录重试，包括已有配置文件带 `loginFailExit=true` 的情况。该行为仅针对本项目的嵌入式 Agent，不修改独立 FRPC CLI 的默认配置。
- 管理端下发配置改用 `ApplyConfig`：先完成原有配置校验、原子替换和重载，再等待认证连接与所有启用代理的注册状态。
- 最多等待 45 秒，覆盖 FRP 默认的 30 秒代理注册重试间隔。超时会说明具体未就绪状态；保留目标配置与内核重试，不悄悄恢复为关闭前的配置。
- 新的成功日志为“配置应用成功：FRPS 已连接，启用隧道已注册”；异步内核退出或注册失败不再被该日志掩盖。注册成功仍不等同于目标服务可达。
- 配置相同的重连不重启工作中的核心，但确认应用结果时仍检查真实就绪状态。

**生效范围：重名根因修复位于服务端配置生成，升级服务端到 v3.2.13 并让客户端收到新配置即可，兼容现有 v3.2.11 Agent。持续重试和准确成功日志则需要将客户端也升级到 v3.2.13。v3.2.12 及更早版本不包含这些修复。**

服务端升级后，Agent 重连注册会自动获取当前权威配置；也可在设备重连后核对日志中的新代理名。旧显示名称不需要修改。对外 TCP/UDP 监听端口仍须按协议避免冲突：显示名可以重复，不代表两个独立隧道能同时独占同一协议、同一监听地址及端口。

当前配置变更仍会重建整个内嵌 FRPC，可能短暂中断该设备的其他隧道；本次没有改成无中断热更新。

## 现场检查

先确认实际客户端版本，并保留关闭和启用前后的完整日志：

```bash
# 客户端宿主机
docker exec frp-agent frp-agent -version
docker logs --since 10m frp-agent

# 服务端宿主机
docker logs --since 10m frp-server
```

不要只截取“配置更新成功”。应继续查看后面的：

- `login to server success`：FRPC 控制连接是否认证成功。
- `start proxy success`：对应隧道是否真正完成注册。
- `login to the server failed` / `no additional retries`：是否首次连接失败后内核退出。
- `already exists` / `port unavailable` / `start error`：是否代理重名、端口冲突或服务端拒绝注册。
- `connect to local service` 等连接错误：已注册，但配置中的客户端目标 IP/端口不可达。

如需读取当前 FRPC 的注册状态，可在客户端容器内访问本机 Admin API（默认面板生成配置使用 127.0.0.1:7400）：

```bash
docker exec frp-agent python3 -c 'import urllib.request; print(urllib.request.urlopen("http://127.0.0.1:7400/api/status", timeout=5).read().decode())'
```

若使用自定义 Admin 端口或认证，应按实际配置调整，不要将 Admin API 直接暴露公网。

还需要区分“服务器端口连接被拒绝”和“能够建立 TCP 连接但业务无响应”，两者排查方向不同。分享日志时请遮盖 Token、密码等敏感信息，但保留错误、时间和对应代理名。
