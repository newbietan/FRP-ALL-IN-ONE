# FRP-ALL-IN-ONE v3.3.0 (Security and Quality Release)

> **重大安全升级与质量基线里程碑版本 (Critical Security and Quality Release)**  
> 本版本彻底修复了包含**未认证静态路由路径穿越与管理员身份伪造链**在内的多项严重安全隐患，正式引入针对国内无备案云服务器的 **IP SAN 自签名 TLS 模式**与 **Agent 证书指纹锁定（Pinning）机制**，并将 Web 控制台默认访问端口切换为标准的 **443** 端口，支持在浏览器中直接打开 `https://<服务器公网IP>` 优雅访问。

---

## 一、 核心更新与安全加固

### 1. 严重与高危安全漏洞修复 (Security Vulnerabilities)

- **静态文件路由未认证路径穿越与 JWT 伪造修复 (CWE-22 / CWE-200，严重)**：
  - 彻底重构 `serve_spa_frontend` 静态路由；
  - 强制执行路径绝对化检查、`.relative_to()` 范围断言与符号链接逃逸防御，杜绝外部未认证请求读取 `data/.jwt_secret` 与 SQLite 数据库文件；
  - 配合 JWT 签名过期强校验，根除攻击者离线伪造管理员 Token 接管控制台的攻击链。
- **初始超级管理员注册防抢占 (CWE-862，高危)**：
  - 服务端初次启动若未预设管理员，系统强制实行 Fail-Closed（安全失败）策略，拒绝任何公网用户的未授权首次注册；
  - 部署脚本中强制引导配置管理员账号，且优先匹配不可变且唯一的数字 `github_id`。
- **OAuth 状态重构与浏览器 Cookie 绑定 (CWE-352 / CWE-384)**：
  - 引入 10 分钟单次有效的高强度随机 state，并严格绑定 `SameSite=Lax`、`HttpOnly`、`Secure` 浏览器 Cookie，彻底防御 OAuth 混淆与 CSRF 攻击；
  - 重定向基准地址统一走服务端可信配置（`FRP_PUBLIC_URL`），防御 Host 头注入攻击。
- **管理员换绑改用受鉴权保护的 POST 请求**：
  - 废弃在 URL Query 参数中传输管理员长期 JWT 的历史做法，换绑操作改为需 Bearer Token 验证的 `POST /api/auth/github/rebind`。
- **Agent 安装凭据权限收敛**：
  - 通用 `install_key` 严格收敛为仅可用于注册新设备，禁止通过提供已有 `client_id` 读取旧设备长期凭证。

### 2. 国内免备案网络支持与默认 443 端口直连

- **控制台默认端口升级为 443（彻底废弃 8080）**：
  - 服务端容器默认端口从 `8080` 升级为 `443`，项目彻底废弃 `8080` 端口；
  - 部署完成后在浏览器中直接输入 `https://<你的服务器公网IP>` 即可进入控制台，**无需输入任何端口号后缀**。
- **自动签发带 IP SAN 的 10 年期自签名证书**：
  - 在未挂载外部 CA 证书且启用自签模式时，容器启动自动调用 OpenSSL 生成包含 `subjectAltName = IP:<公网IP>,IP:127.0.0.1,DNS:localhost` 的高强度证书，持久化于 `data/certs/self_signed/`；
  - 握手流量不包含任何域名 SNI，**天然绕过国内云厂商机房针对未备案域名的拦截阻断**，全程保持 TLS 1.3 强加密。
- **Agent 客户端证书指纹锁定（Pinning）**：
  - Agent 新增 `-tls-fingerprint` 参数与 `FRP_AGENT_TLS_FINGERPRINT` 环境变量；
  - 客户端握手时自动校验服务端叶子证书的 SHA256 指纹，**即便使用自签证书，依然 100% 免疫中间人劫持（MITM）**；
  - 新增 `-insecure-tls` 参数支持跳过 CA 证书链校验。
- **一键脚本自动注入指纹**：
  - 服务端生成客户端一键命令时，自动将自身证书的 SHA256 指纹注入脚本中，客户端粘贴即可一键秒级接入。

---

### 3. 宿主机特权与 Docker Socket 最小化隔离

- **Compose 模板收紧**：
  - 默认 Compose 模板中注释掉 `/var/run/docker.sock` 挂载，推荐在宿主机侧进行版本维护。
- **客户端一键命令默认不暴露 Socket**：
  - 一键生成命令默认不再挂载 Docker Socket；
  - 仅在管理员在面板显式声明 `FRP_ENABLE_REMOTE_UPGRADE=1` 时才按需放行，并明确打印特权警告。

---

### 4. 供应链安全与代码质量提升 (Quality & Supply Chain)

- **JWT 库迁移至 PyJWT**：
  - 移除存在废弃依赖和时序侧信道隐患的 `python-jose` / `ecdsa`，全面切换至行业标准的 `PyJWT[crypto]>=2.10.1`，并强制校验 `exp` 过期声明。
- **生产依赖哈希锁定**：
  - 生成带完整 SHA-256 哈希校验的 `server/requirements.lock`，服务端 Dockerfile 构建时启用 `--require-hashes`。
- **前端高危依赖清除**：
  - 升级 `vite@6.4.5`，修复了 Vite 6.4.3 及以下版本的 launch-editor RCE 与目录穿越问题；`npm audit` 漏洞降至 0。
- **Go 依赖与基础镜像升级**：
  - 升级 `github.com/gorilla/websocket` 至 `v1.5.3`（修复 PRNG 弱随机数）；
  - 升级 `golang.org/x/net` 至 `v0.60.0`（修复 HTTP/2 服务端 DoS 等隐患）；
  - 基础镜像升级至 `Alpine 3.23`，Go 编译工具链升级至 `Go 1.26.10`。

## 二、 旧版本升级与迁移指南 (断代安全升级说明)

> **重大架构与安全断代说明**：<br>
> **v3.3.0 已彻底废弃 8080 端口，且不再提供针对旧版本 (< v3.3.0) 的就地平滑升级兜底。**<br>
> 鉴于旧版本存在严重的未认证静态文件读取缺陷，历史生成的 JWT 密钥及凭据可能已存在泄露风险。为了彻底根除安全隐患并切换至全新 443 原生 TLS 架构，**官方强烈建议并要求所有旧版本用户放弃就地平滑升级，采取手动移除旧容器与旧数据、全新部署 v3.3.0 的方式**：

### 1. 旧版本用户升级步骤（手动移除并重新部署）

1. **备份必要业务配置**：在原有旧面板中记录已配置的客户端与隧道参数（端口、协议、目标 IP 等），旧的敏感凭据（如 `.jwt_secret`、旧 Token）一律废弃。
2. **彻底移除旧容器与旧数据**：
   ```bash
   # 停止并移除旧版容器
   docker rm -f frp-server frp-agent 2>/dev/null || true
   # 清理旧数据目录（彻底清除可能泄漏的旧密钥）
   rm -rf ./data /app/data /opt/frp
   ```
3. **重新部署全新 v3.3.0 服务端**：
   在宿主机执行一键部署命令，选择默认的【纯 IP 自签 HTTPS 模式】：
   ```bash
   curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/main/deploy/deploy.sh | sudo bash
   ```
4. **客户端重新执行一键接入**：
   登录全新 Web 控制台（直接打开 `https://<服务器公网IP>`），点击「添加新设备」，复制带有安全指纹的最新命令在内网机器运行即可。
