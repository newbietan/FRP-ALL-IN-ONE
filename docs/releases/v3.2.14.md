# FRP-ALL-IN-ONE v3.2.14

本版本彻底修复客户端日志采集器缓冲区重复落盘导致的日志膨胀与“伪重载风暴”问题，新增日志单文件按体积切分轮转与过期清理机制，并在容器与 Agent 内部全面引入孤儿僵尸进程回收。

## 核心修复

### 彻底消除日志缓冲区回放放大（消除“伪重载风暴”）

- **根因确认**：在旧版本中，`Collector` 的内部缓冲区同时承担“内存最近日志查询”与“待落盘文件缓冲”两种职能，且在定时刷盘（每 5 秒）时未清空待写切片，导致整块历史缓冲被无条件重复追加写入文件。这造成单日日志膨胀数十万行、尾部时间戳永久冻结在启动时刻的假象（此前排查中被误判为“配置重载风暴”）。
- **待写切片与查询缓存解耦**：
  - 内存环形缓冲区专职保留最近 1000 条日志供 API 与面板展示；
  - 待写切片在每次 `flush()` 落盘后立即原子置空；
  - **零写入防御**：当无新增日志时，刷盘流程立即返回，不产生任何磁盘写入与文件同步（Sync），日志大小严格保持不变。

### 日志单文件大小轮转与过期清理（20 MB / 保留 3 份）

- **20 MB 单文件轮转**：单个日志文件达到 20 MB 上限后自动切分归档（`.1.log` ~ `.3.log`），活跃文件重置继续写入，防止极端情况下日志耗尽宿主机磁盘空间。
- **多卷无损合并读取**：`ReadLogFile(date)` 自动按时间正序合并历史分卷与当前活跃日志，提供完整连续的单日日志视图。
- **过期自动清理**：每天轮转时自动扫描并清理 7 天前已过期的历史日志文件。

### 容器与进程级孤儿僵尸进程回收（PID 1 Reaper）

- **镜像引入 tini 作为 Entrypoint**：客户端基础镜像内置 `tini` 并将其作为容器 `ENTRYPOINT ["/sbin/tini", "--", "frp-agent"]`，原生实现容器内 PID 1 init 语义，自动回收孤儿僵尸进程并妥善转发系统信号。
- **部署脚本注入 `--init`**：服务端生成的 Linux/macOS 及 Windows 容器一键启动脚本中默认添加 `--init` 参数。
- **Agent 内置兜底回收器**：在裸机、系统服务或自建容器等以 `PID == 1` 运行且未配置 init 的场景下，Agent 自动启动基于 `SIGCHLD` 与非阻塞 `Wait4` 的孤儿进程回收器，并在升级执行事务期间与 Go runtime `os/exec` 协同暂停/恢复，防止产生等待竞争。

### Agent 停机优雅刷盘

- 在 Agent 优雅退出流程中补充显式调用 `logCollector.Stop()`，确保待写日志完整落盘并安全释放文件句柄。

## 升级与迁移

1. **客户端须升级到 v3.2.14 才能消除日志回放缺陷**：日志回放发生在 Agent 本地采集器，升级客户端后无需清空配置或重连隧道。
2. 已受旧版本影响导致日志文件过大的设备，可在宿主机执行以下命令清空已污染的历史日志文件（释放磁盘空间）：
   ```bash
   docker exec frp-agent sh -c ': > /opt/frp/logs/frpc-*.log'
   ```
3. 服务端推荐同步升级到 v3.2.14，以获得最新容器启动脚本中的 `--init` 支持。

服务端宿主机升级命令：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.2.14/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.2.14
```

详见 [升级说明](https://github.com/newbietan/FRP-ALL-IN-ONE/blob/v3.2.14/docs/upgrade.md)。
