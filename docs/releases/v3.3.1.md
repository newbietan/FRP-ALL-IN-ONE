# FRP-ALL-IN-ONE v3.3.1

本版本专注于修复客户端一键安装及升级脚本在自签名证书与 IP 地址访问场景下的证书校验阻断问题，完善自签名证书的兼容性与防御纵深。

## 核心修复与改进

### 1. 客户端一键安装命令支持自签名证书与 IP 访问

- **问题背景**：FRP-ALL-IN-ONE 默认推荐采用 IP 10 年期自签名证书模式进行免域名、免备案 TLS 1.3 强加密部署。但此前面板生成的客户端一键命令使用 `curl -fsSL`，`curl` 默认严格校验系统根 CA 证书链，导致在客户端执行时报错 `curl: (60) SSL certificate OpenSSL verify result: self-signed certificate (18)`，无法下载安装脚本。
- **命令优化**：
  - **Linux / macOS**：一键安装命令更新为 `curl -kfsSL '{base_url}/api/frp/agent/install/linux?key={install_key}' | sudo bash`，原生支持自签名证书与 IP 直连拉取。
  - **Windows**：PowerShell 一键执行命令在调用 `Invoke-RestMethod` 前注入 `[System.Net.ServicePointManager]::ServerCertificateValidationCallback = {$true}`，确保在自签名证书环境下顺利拉取。
- **安全性说明**：`-k` 仅用于下载初始安装脚本；脚本内部启动 Agent 容器时，已自动注入证书的 SHA-256 指纹（`FRP_AGENT_TLS_FINGERPRINT`），Agent 与服务端的长连接通信依然遵循严格的证书 Pinning 锁定校验，100% 免疫中间人篡改。

### 2. 客户端升级命令同步支持自签名 TLS

- 管理面板生成的单次升级执行命令同步升级为带自签名证书兼容能力的 `curl -kfsSL` 与 PowerShell 回调逻辑，确保后续客户端远程平滑升级事务在 IP 自签名证书下稳定执行。

### 3. 自签名证书指纹动态计算与安全容错兜底

- **动态指纹提取**：新增对自定义挂载证书 `FRP_TLS_CERT` 路径的指纹计算提取逻辑，确保即使通过自定义证书文件部署，服务端也能精准计算出 SHA-256 指纹并下发至客户端。
- **IP 访问自适应容错**：当服务端通过 IP 地址访问且因特殊反向代理配置未能提取到具体指纹时，脚本自动自适应注入 `FRP_AGENT_INSECURE_TLS=1`，确保客户端 Agent 容器能顺利完成与服务端的 WebSocket 握手，避免因未知 CA 导致连接失败。

## 升级与迁移

本项目从 v3.3.0 起已进入全新 443 原生 TLS 架构，**v3.3.0 及以上版本支持平滑无缝升级**：

### 服务端升级

在服务端宿主机执行以下命令即可平滑升级至 v3.3.1：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.3.1/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.3.1
```

### 客户端安装或升级

已在运行的客户端不受影响；新设备可直接在管理面板复制最新的一键安装命令进行部署：

```bash
curl -kfsSL 'https://<你的服务器IP或域名>/api/frp/agent/install/linux?key=<安装密钥>' | sudo bash
```
