# FRP-ALL-IN-ONE v3.2.12

本版本修复 Web 设备离线后最后心跳显示原始时间戳的问题，并完善服务端与客户端部署脚本的 Docker 开机自启配置。

## 核心修复

### 最后心跳时间统一格式化

- 将后端秒级时间戳转换为 `YYYY-MM-DD HH:mm:ss`，不再直接展示一串数字。
- 首次加载、完整状态同步和实时在线/离线事件均使用浏览器本地时区，避免 UTC 与本地时间混用。
- 兼容毫秒时间戳与 ISO 时间；尚无心跳、空值及无效时间显示 `-`。
- 修正前端 API 中 `last_seen` 的类型定义，与后端秒级数值保持一致。

### 补齐 Docker 开机自启配置

- 服务端和客户端容器原本均已配置 `restart: always`；此次补齐宿主机 Docker 服务的自启配置，避免 Docker 当前运行正常却未加入开机启动的遗漏。
- Linux 部署脚本每次都会尝试通过 systemd 或 OpenRC 启用 Docker 自启，而不再只在 Docker 未运行时配置。
- 无法启用服务、缺少受支持的服务管理器或客户端以非 root 身份安装时，明确给出检查提示，不静默宣称自启已完成。
- Windows/macOS 安装提示中说明：需开启 Docker Desktop 的“登录时启动”；这不等于无人登录情况下的开机运行。

## 升级注意事项

1. 心跳展示修复随服务端 Web 界面更新生效，升级后重新加载页面即可；无需仅为此项修复升级客户端。
2. **容器镜像升级不会自动修改宿主机 Docker 服务的开机启动配置。** 已有安装请在服务端和客户端各自的宿主机检查并补齐：

   ```bash
   # systemd（如 Ubuntu / Debian）
   sudo systemctl enable --now docker
   systemctl is-enabled docker

   # OpenRC（如 Alpine；按系统选择，不要与上面的命令同时执行）
   sudo rc-update add docker default
   sudo rc-service docker start
   ```

3. Windows/macOS 请在 Docker Desktop 中开启登录时启动。需要无人值守开机运行时，建议使用 Linux Docker Engine；Rootless Docker 或自定义环境需自行配置相应服务。
4. 可用 `docker inspect --format '{{.HostConfig.RestartPolicy.Name}}' frp-server` 或将容器名替换为 `frp-agent` 检查容器策略；应为 `always`。策略缺失时可执行 `docker update --restart always <容器名>`。
5. 不要为补齐宿主机自启而重新运行服务端 `deploy.sh`；该脚本包含历史容器清理逻辑。已有服务升级请使用面板或专用升级脚本。

服务端宿主机升级命令：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.2.12/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.2.12
```

升级切换期间连接可能短暂中断，不是零停机。默认保留数据库、客户端 ID、认证信息和持久化配置；不要先删除旧容器、设备记录或数据卷。详见 [升级说明](https://github.com/newbietan/FRP-ALL-IN-ONE/blob/v3.2.12/docs/upgrade.md)。

## 回归验证

- 新增前端测试，覆盖秒/毫秒时间戳、ISO 时间、本地时区转换及无效/缺失值。
- 新增部署脚本测试，通过模拟 systemd/OpenRC 验证 Docker 已运行时仍配置自启，以及失败警告、Desktop 提示、重启策略和脚本语法。
- 前端 CI 增加 `npm test`，与类型检查和生产构建共同执行。
- 宿主机服务配置测试使用模拟命令，不操作测试机器的实际 Docker 服务，也不代表已进行物理主机重启或 Docker Desktop 实机验证。
