# FRP-ALL-IN-ONE v3.3.3

本版本专注于优化 Docker 客户端守护进程与 FRP 容器的开机自启与故障自愈能力，彻底解决宿主机开关机或重启后局域网 DHCP IP 变动导致穿透服务失效的问题，重塑控制台隧道配置与地址推荐交互。

---

## 核心改进与功能优化

### 1. 彻底解耦宿主机局域网 IP，免疫开关机与 DHCP 变动导致的穿透中断

- **问题背景**：家用路由器或交换机默认通过 DHCP 动态分配 IP。客户端主机开关机或重启后，内网 IP 经常发生变化（如从 `192.168.1.100` 变为 `192.168.1.105`）。此前部署脚本会将初次安装时的内网 IP 静态注入容器环境变量（`-e FRP_HOST_IP`），且控制台提示用户一键填入该动态 IP。这导致宿主机一旦重启并换了 IP，隧道配置因找不到原 IP 而彻底失效。
- **优化方案**：
  - **移除静态环境变量锁定**：客户端部署脚本不再向容器注入 `-e FRP_HOST_IP`，避免旧 IP 被持久化固化在容器内，使 Agent 能在每次系统启动或网络变动时动态感知当前网络状态。
  - **Linux Host 模式直通闭环（推荐 `127.0.0.1`）**：在 Linux 原生 Host 模式下，容器与宿主机共享网络栈，转发宿主机本机服务（如 SSH :22、Web :80 等）推荐直接使用 `127.0.0.1`，完全无需关心路由器分配的局域网 IP 怎么变动，永久有效。
  - **Windows / macOS Docker Desktop 环境（推荐 `host.docker.internal`）**：针对 Docker Desktop 虚拟机环境，推荐使用 Docker 内置的宿主机网桥虚拟域名 `host.docker.internal`，彻底摆脱物理网卡 DHCP 租约变动的影响。

### 2. 增强 Docker 服务与 FRP 客户端容器的开机自启

- **系统服务级自启**：在 Linux 安装脚本中补充启用了 `containerd.service` 自启（`systemctl enable --now docker containerd`），与容器 `--restart always` 策略配合，保证宿主机断电或重启后无需人工干预即可全自动拉起。
- **开机网络未就绪容错**：开机自启阶段，Docker 容器可能先于物理网卡完成 DHCP 协商启动。Agent 内部具备完善的指数退避重连机制，在网络就绪后可毫秒级自动恢复连接与指标上报。

### 3. Agent 动态多通道网络探测能力升级

- 增强了 `getOutboundIP()` 内核路由免发包探测逻辑，由单一目标扩展为多通道公网与高可用国内 DNS（`8.8.8.8`、`1.1.1.1`、`223.5.5.5`），在复杂隔离内网、多网卡或特定防火墙环境下均能高可靠地动态探测到当前主物理出接口 IP，并在每次心跳上报时自动同步至控制台。

### 4. 控制台隧道配置地址智能推荐与交互重塑

- **消除误导性警告**：移除了原先不论操作系统均警告“127.0.0.1 指向容器内部”的误导性提示，改为根据客户端平台智能适配：
  - **Linux 客户端**：新建映射默认填入 `127.0.0.1`，并展示绿色安心提示（*“已选择 127.0.0.1：Linux Host 模式直通宿主机，完全不受路由器开机重启及 DHCP IP 变动影响”*）；
  - **Windows / macOS 客户端**：默认推荐填入 `host.docker.internal`；若用户误填 `127.0.0.1`，显示友好提示卡片并提供一键填入 `host.docker.internal` 按钮；
  - **物理局域网 IP 引导**：嗅探到的局域网 IP 徽章增加清晰标注，提示其主要适用于转发“同一局域网下的其他物理设备（如旁路由、NAS 等）”。

## 升级与迁移

本项目从 v3.3.0 起已进入全新 443 原生 TLS 架构，**v3.3.0 及以上版本支持平滑无缝升级**：

### 服务端平滑升级

在服务端宿主机执行以下命令即可平滑升级至 v3.3.3：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.3.3/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.3.3
```

### 客户端安装或升级

已在运行的客户端不受影响；新设备可直接在管理面板复制最新一键安装命令进行部署。若旧客户端曾因局域网 IP 变动遇到隧道失效，推荐在控制台中将隧道本地 IP 调整为 `127.0.0.1`（Linux）或 `host.docker.internal`（Windows/macOS）即可永久免疫。
