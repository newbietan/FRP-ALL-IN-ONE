# FRP-ALL-IN-ONE v3.2.11

本版本修复客户端新增隧道时的默认配置校验错误，以及 FRPC 重载期间本机管理端口 `7400` 的释放竞态。

## 核心修复

### 普通隧道不再误报带宽模式错误

- 首次启动与配置更新统一先补全 FRP 代理、访问者默认值，再进行校验。
- 未设置 `transport.bandwidthLimitMode` 的 SSH/TCP 隧道正确使用默认值 `client`，不再报 `bandwidth limit mode should be client or server`。
- 显式设置的 `client`、`server` 模式仍保留；非法值继续拒绝，且不覆盖原有配置、不停止正在工作的核心。

### 重载等待旧核心完整退出

- 启动、停止、重启与配置更新使用同一操作锁，避免并发创建核心或覆盖配置。
- 移除固定 500ms 延时，等待旧核心 `Run` 返回、控制连接和管理监听释放后再启动新核心。
- 默认退出等待上限为 15 秒；超时会报告错误并保留旧服务占位，不启动第二个核心争抢端口。
- 新核心创建失败时尝试恢复旧配置和旧核心；相同配置的正常重连不触发无意义的重启。
- 补充重启、停止及退出健康状态写入失败的日志。

此修复针对自身旧核心的释放竞态，不会强制终止其他占用 `7400` 的进程。若端口由其他程序或重复部署的容器占用，仍需单独排查。

## 回归验证

- 新增普通 SSH 配置、合法/非法带宽模式、访问者默认值及旧配置保护测试。
- 新增延迟释放端口、退出超时、创建失败恢复、连续与并发生命周期测试。
- 使用真实 FRPS 和 FRPC 验证：认证后新增未配置限速模式的 TCP 隧道，重载成功并实际转发测试流量。
- Agent CI 启用 Go race detector；补齐真实 FRPS 测试所需的间接依赖与校验信息，不升级既有依赖版本。
- 本地已通过全量竞态测试、生命周期重复压力验证、真实隧道重复转发验证、静态检查及 Linux 客户端构建。

## 升级说明

**本次核心修复位于客户端，仅升级服务端不足以生效，客户端也必须升级到 v3.2.11。**

1. 先升级服务端到 v3.2.11，以便面板下发相同版本的客户端升级目标。
2. 支持容器自升级的 Agent 可从面板升级；旧版或缺少 Docker Socket 的安装，使用面板生成的宿主机手动命令完成迁移。
3. 完成后确认客户端版本为 v3.2.11，再创建或修改隧道，检查配置更新和隧道连通情况。

服务端宿主机升级命令：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.2.11/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.2.11
```

升级切换及内核重载期间连接可能短暂中断，不是零停机。默认保留数据库、客户端 ID、认证信息及持久化配置；不要先删除旧容器、设备记录或数据卷。具体迁移与恢复步骤见 [升级说明](https://github.com/newbietan/FRP-ALL-IN-ONE/blob/v3.2.11/docs/upgrade.md)。
