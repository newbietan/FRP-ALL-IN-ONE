# FRP-ALL-IN-ONE v3.2.10

本版本集中修复服务端、客户端与宿主机脚本的升级链路，并统一使用 Docker。

## 重要兼容性说明

- **移除 Podman 支持，仅支持 Docker。** 历史非 Docker 安装请先备份数据库、密钥、证书和客户端配置，再手动迁移；新脚本不会跨引擎删除旧容器。
- 升级是保留配置、带健康检查和失败回滚的容器替换，**并非零停机**；切换期间管理连接和隧道会短暂中断，随后重新连接。
- 已启用的 Watchtower 等外部自动更新器应先停用，避免绕过升级事务或与其并发执行。

## 升级修复

- 服务端宿主机脚本与面板升级统一使用独立事务执行器，不再拉取指定版本后却按 Compose 的 `latest` 重建。
- 使用不可变镜像 ID，并验证目标镜像版本、角色与升级协议；通过连续健康检查后才确认成功，失败则恢复旧容器与配置。
- 协商 Docker API 版本，保留设备、命名空间、环境变量和实际挂载，兼容空挂载列表及 Windows 盘符绑定。
- 健康检查读取新容器实际启动参数，并等待 Docker exec 命令完成后读取退出码，避免端口变化或执行竞态导致误回滚；失败状态保留最后一次检查错误。
- 客户端手动升级命令可通过新凭据重试原活动任务，避免下载或拉取失败后持续被“已有任务”阻塞。
- 修复 macOS Docker Desktop Socket 探测与 Windows PowerShell 预期探测失败导致脚本提前退出的问题。
- 卸载脚本支持核实以镜像 ID 启动的项目容器，仍拒绝删除无关资源。

## 构建、校验与文档

- 统一服务端、Agent、前端和构建默认版本为 `3.2.10`，同步前端依赖锁文件的项目版本。
- 本地镜像构建显式传递真实版本，避免镜像标签、协议标签和程序版本不一致。
- 修正客户端响应的 ORM 临时属性处理；隧道开关只接受布尔值，认证拒绝无效 JWT subject。
- 补充升级、脚本、客户端任务及参数校验回归测试，并新增真实 Docker 升级/回滚 CI 与 PowerShell 语法检查。
- 详细操作和异常恢复见 [升级说明](https://github.com/newbietan/FRP-ALL-IN-ONE/blob/v3.2.10/docs/upgrade.md)。

## 如何升级

建议先升级服务端，再升级客户端。已支持升级协议且挂载 Docker Socket 的安装可从面板升级；旧版安装先使用宿主机命令完成迁移。

服务端宿主机命令：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.2.10/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.2.10
```

客户端请从面板生成专属升级命令，凭据十分钟内有效且单次使用。使用 Compose 管理服务时，请同步固定目标镜像标签，避免后续重建覆盖升级结果。

## 容器镜像

以下镜像均提供 `linux/amd64`、`linux/arm64` 架构：

- 服务端：`sgccr.ccs.tencentyun.com/frp-all-in-one/frp-server:v3.2.10`
- 客户端：`sgccr.ccs.tencentyun.com/frp-all-in-one/frp-agent:v3.2.10`

## 客户端二进制

| 文件 | 平台 |
| --- | --- |
| `frp-agent-linux-amd64` | Linux x64 |
| `frp-agent-linux-arm64` | Linux ARM64 |
| `frp-agent-darwin-amd64` | macOS Intel |
| `frp-agent-darwin-arm64` | macOS Apple Silicon |
| `frp-agent-windows-amd64.exe` | Windows x64 |
| `SHA256SUMS` | 二进制 SHA-256 校验清单 |

容器客户端是推荐部署方式；直接使用二进制不具备容器事务自升级能力。挂载 Docker Socket 等价于授予宿主机管理权限，仅在可信设备上启用。
