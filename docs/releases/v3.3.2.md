# FRP-ALL-IN-ONE v3.3.2

本版本专注于修复客户端安装及升级命令中的中间人（MITM）拦截风险，强化传输链路指纹校验，并显著优化控制台客户端远程升级完成后的自动关闭与交互体验。

---

## 核心安全修复与改进

### 1. 客户端安装与升级命令引入公钥 Pinning 强校验机制

- **问题背景**：此前版本在自签名证书及 IP 访问场景下，为防止 `curl` 报 CA 证书链校验错误，命令采用了 `curl -kfsSL ... | sudo bash`，在存在恶意中间人（如不可信 Wi-Fi、网关劫持、ARP 欺骗）的环境中，攻击者理论上可拦截下载流量并注入恶意脚本。
- **安全加固**：
  - **Linux / macOS**：一键安装与升级命令全面引入 `--pinnedpubkey "sha256//{pubkey_pin}"` 机制，在 TLS 握手阶段对服务器公钥执行严格的哈希校验（Pinning）。若存在任何中间人篡改或出示非本服务器公钥，`curl` 将直接报错（退出码 90）并阻断退出，从根源杜绝恶意脚本被下载与执行。
  - **Windows (PowerShell)**：移除原本无条件信任所有证书的 `$true` 回调，改为在 `ServerCertificateValidationCallback` 中计算对端证书的原始 SHA-256 指纹比对。只有持有匹配指纹的服务器才能完成握手，否则直接终止。
  - **受信 CA 自适应**：对于配置了已备案域名或 Let's Encrypt 证书的站点，系统自动输出严格遵循系统受信任 CA 证书链的标准 `curl -fsSL` 命令（无 `-k`）。

### 2. 严格遵循 Fail-Closed 原则，移除隐式无校验降级

- 移除了在未提取到证书指纹时根据 IP 访问自动注入 `FRP_AGENT_INSECURE_TLS=1` 的隐式降级后门。
- 只有管理员显式通过环境变量声明开启该测试选项时，才会允许客户端跳过 CA 校验，并在 Agent 启动时输出醒目的安全告警。

### 3. 控制台 Agent 远程升级体验优化（自动提示与平滑关闭）

- **体验痛点**：在 Web 控制台下发 Agent 远程升级信号后，即使客户端已拉取新镜像并顺利重启生效，升级对话框依然长久停留在界面上，必须手动点击右上角关闭按钮。
- **交互优化**：
  - 增加对升级任务完成状态（`succeeded`）的实时监听。
  - 升级成功后，操作按钮立即转为绿色“✓ 升级成功，窗口即将自动关闭...”，同时触发全局操作成功提示（Toast）。
  - 弹窗在 1.8 秒后平滑自动关闭，并自动重新拉取最新的设备列表与版本数据，交互体验无缝顺畅。

### 4. 前端 Markdown 渲染组件增加协议白名单校验

- 针对系统更新日志中的 Markdown 渲染组件（`MarkdownView`），增加对解析链接的协议白名单断言，严格仅允许 `http:`、`https:`、`/` 与 `#` 开头的安全超链接，杜绝潜在的 `javascript:` 伪协议 XSS 风险。

## 升级与迁移

本项目从 v3.3.0 起已进入全新 443 原生 TLS 架构，**v3.3.0 及以上版本支持平滑无缝升级**：

### 服务端平滑升级

在服务端宿主机执行以下命令即可平滑升级至 v3.3.2：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.3.2/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.3.2
```

### 客户端安装或升级

已在运行的客户端不受影响；新设备可直接在管理面板复制最新带公钥 Pinning 的一键安装命令进行部署：

```bash
curl -kfsSL --pinnedpubkey "sha256/<公钥PIN>" 'https://<你的服务器IP或域名>/api/frp/agent/install/linux?key=<安装密钥>' | sudo bash
```
