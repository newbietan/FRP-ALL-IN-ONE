# FRP-ALL-IN-ONE v3.3.4

本版本专注于修复客户端升级完成后控制台升级弹窗状态未能即时刷新、需手动刷新浏览器才能看到新版本并自动关闭的问题，实现客户端升级链路端到端全自动无缝闭环。

---

## 核心改进与问题修复

### 1. 修复前端 WebSocket 全量同步对象合并顺序缺陷

- **问题原因**：在 Web 控制台处理全量数据同步（`full_sync`）时，对象合并逻辑错误地将旧缓存数据放在了新数据后面（`{ ...fresh.agentInfo, ...old.agentInfo }`）。导致服务端推送包含最新客户端版本号（`agent_version: "3.3.4"`）时，旧对象的历史版本（`agent_version: "3.3.2"`）反向覆盖了最新数据，造成新版本在前端被直接丢弃。
- **修复方案**：修正合并顺序为 `{ ...old.agentInfo, ...fresh.agentInfo }`，确保服务端推送的最新版本号及元数据具有最高优先级。

### 2. 升级弹窗重构为动态响应式绑定（`liveDevice`）

- **问题原因**：弹窗此前绑定的是打开瞬间捕获的静态设备快照，在客户端重启并完成升级后，静态快照里的版本号永远定格在旧版本，从而使得版本一致性检查永远不通过，弹窗既无法显示新版本，也无法自动触发关闭。
- **修复方案**：弹窗内部全面升级为动态关联全局设备状态（`liveDevice`）。一旦客户端重启就绪并上报新版本，弹窗中的当前版本即刻秒级更新，自动关闭逻辑也能即时捕捉并平滑关闭弹窗。

### 3. 服务端在 Agent 重新注册与任务成功时主动广播同步

- **修复方案**：
  - 当客户端完成容器切换重启并发送 `register` 注册消息时，服务端主动向所有连接的 Web 控制台广播 `_broadcast_dashboard_sync` 全量数据同步；
  - 当升级任务在服务端确认达到 `succeeded` 终态时，即时广播同步，彻底消除此前因缺乏主动通知而必须依赖手动刷新网页（F5）的弊端。

## 升级与迁移

本项目从 v3.3.0 起已进入全新 443 原生 TLS 架构，**v3.3.0 及以上版本支持平滑无缝升级**：

### 服务端平滑升级

在服务端宿主机执行以下命令即可平滑升级至 v3.3.4：

```bash
curl -fsSL https://raw.githubusercontent.com/newbietan/FRP-ALL-IN-ONE/v3.3.4/deploy/upgrade.sh -o /tmp/frp-upgrade.sh
sudo bash /tmp/frp-upgrade.sh v3.3.4
```

### 客户端平滑升级

在 Web 控制台的「设备管理」列表中，直接点击可升级设备对应的「可升级」按钮并发送升级信号，升级成功后弹窗将自动更新版本并平滑关闭，无需手动刷新网页。
